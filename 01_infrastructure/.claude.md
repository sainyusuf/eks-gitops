# Infrastructure Layer - AWS Foundation

## Project Context
This subproject manages the foundational AWS infrastructure for the EKS GitOps platform:
- VPC with public/private subnets across 3 availability zones
- NAT Gateways for private subnet internet access
- Route53 hosted zone for domain management
- Supporting networking components

## Technology Stack
- **IaC Tool**: Terraform
- **AWS Services**: VPC, Subnets, NAT Gateway, Internet Gateway, Route Tables, Route53
- **State Backend**: S3 (configured via bootstrap CloudFormation)
- **Region**: eu-central-1

## Directory Structure
```
01_infrastructure/
├── main.tf           # VPC module configuration
├── outputs.tf        # VPC outputs for EKS layer
├── provider.tf       # AWS and Terraform providers
├── variables.tf      # Input variables
└── terraform.tfvars  # Variable values
```

## Key Principles

### 1. Network Design
- **3 AZ deployment** for high availability
- **Public subnets** (CIDR: 10.0.0.0/20, 10.0.16.0/20, 10.0.32.0/20) for load balancers
- **Private subnets** (CIDR: 10.0.1.0/24, 10.0.2.0/24, 10.0.3.0/24) for EKS nodes
- **Single NAT Gateway** (cost optimization, can be changed to one per AZ for HA)

### 2. Tagging Strategy
All resources tagged with:
- `Environment`: Production/Staging
- `Owner`: Team/individual responsible
- `GitHubRepo`: Source repository
- **Karpenter discovery tags**: Applied to subnets for auto-discovery

### 3. State Management
- Remote state stored in S3
- State locking via DynamoDB
- Bootstrap resources created via CloudFormation (see `00_bootstrap/`)

## Guidelines for Modifications

### Adding New Subnets
When adding subnets, ensure:
1. CIDR blocks don't overlap
2. Proper route table associations
3. Karpenter discovery tags on private subnets
4. Outputs updated for EKS layer consumption

### Changing NAT Gateway Strategy
Current: Single NAT Gateway (cost-optimized)
HA Option: One NAT Gateway per AZ
```hcl
enable_nat_gateway     = true
single_nat_gateway     = false  # Change to false for HA
one_nat_gateway_per_az = true   # Add this
```

### DNS Management
- Route53 hosted zone: `tukang-awan.com`
- Name servers must be configured in domain registrar
- ACM certificates created separately in EKS layer

## Dependencies
- **Upstream**: None (foundational layer)
- **Downstream**: `02_eks` (consumes VPC outputs)

## Common Operations

### Initial Deployment
```bash
cd 01_infrastructure
terraform init
terraform plan
terraform apply
```

### Viewing Outputs
```bash
terraform output
terraform output -json | jq
```

### Destroying (⚠️ Careful!)
```bash
# Ensure 02_eks is destroyed first!
terraform destroy
```

## Cost Optimization
- Single NAT Gateway: ~$32/month + data transfer
- Can use VPC endpoints for AWS services to reduce NAT costs
- Consider NAT instances for dev environments

## Security Considerations
- Private subnets have no direct internet access
- All egress traffic routes through NAT Gateway
- Security groups managed at EKS layer
- Network ACLs at default (allow all) - can be hardened

## Outputs Used by EKS Layer
- `vpc_id`: VPC identifier
- `private_subnets`: List of private subnet IDs for EKS nodes
- `public_subnets`: List of public subnet IDs for load balancers
- `route53_zone_id`: Hosted zone for DNS records

## Troubleshooting

### Issue: Terraform state locked
```bash
# Check lock info
aws dynamodb get-item --table-name terraform-locks \
  --key '{"LockID":{"S":"terraform-state-bucket/path/terraform.tfstate"}}' \
  --region eu-central-1

# Force unlock if needed
terraform force-unlock <LOCK_ID>
```

### Issue: CIDR exhaustion
- Evaluate actual IP usage
- Consider larger CIDR blocks for private subnets
- Document IP allocation plan
